1 · Comprensión del negocio

Falso negativo (fraude no detectado): pérdida directa del monto y exposición operativa. Es el error más caro.

Falso positivo (legítima bloqueada): costo de revisión y fricción con el cliente. Tolerable en baja proporción.

Consecuencia: se prioriza el recall sin descuidar la precisión → el umbral se elige maximizando F2, y la métrica de comparación es PR-AUC (la accuracy sería engañosa: predecir "nunca fraude" daría 99,4 %).

Hallazgo de calidad: el archivo es una muestra no uniforme

El índice original (Unnamed: 0) muestra que Fraud.csv contiene el tramo final del simulador más todos los fraudes previos. Resultado: los steps 1–{{ d.sampling.legit_steps[0] - 1 }} tienen sólo fraudes ({{ '{:,}'.format(d.sampling.fraud_only_before)|es }}) y los steps {{ d.sampling.legit_steps[1] + 1 }}–{{ d.steps[1] }} también ({{ d.sampling.fraud_only_after }}). La tasa global de {{ ('%.2f' % (d.fraud_rate * 100))|es }} % está inflada: en la ventana con ambas clases es {{ ('%.2f' % (d.sampling.window_rate * 100))|es }} %.

Decisiones: (1) no se usan step ni day como variables, para que el modelo no aprenda "temprano = fraude"; (2) se verificó que esos fraudes son representativos (vacían la cuenta en {{ ('%.1f' % (d.sampling.drain_before * 100))|es }} % vs {{ ('%.1f' % (d.sampling.drain_window * 100))|es }} %, misma distribución horaria) y se conservan para entrenar; (3) la evaluación se reporta también sólo dentro de la ventana con ambas clases; (4) un modelo entrenado sin esos fraudes logra PR-AUC {{ ('%.4f' % m.results[m.chosen ~ '__solo_ventana'].test.pr_auc)|es }}: el resultado no depende del artefacto.

El hallazgo clave: el fraude vacía la cuenta

El {{ ('%.1f' % (d.drain.fraude_que_vacia * 100))|es }} % de los fraudes transfiere o extrae exactamente todo el saldo de la cuenta de origen. Entre las {{ '{:,}'.format(d.drain.n_vacia)|es }} operaciones que lo hacen, el {{ ('%.2f' % (d.drain.p_fraude_si_vacia * 100))|es }} % son fraude. Es un comportamiento del simulador PaySim (el estafador toma control de la cuenta y la vacía), coherente con el negocio pero mucho más limpio que en la realidad. Se convirtió en las variables drainsOrigin y amountMinusOrigBalance, y se usó como línea base que todo modelo debe superar.

3 · Preparación de los datos

Se excluye

  • isFlaggedFraud: lo indica la consigna.
  • Unnamed: 0: índice exportado, sin significado.
  • nameOrig / nameDest: ~100 % de valores únicos; codificarlos memorizaría cuentas. Sólo se conserva el prefijo del destino (C = cliente, M = comercio).
  • step y day como variables: en una partición temporal el modelo vería días futuros que nunca existieron en entrenamiento. Se usa la hora del día.
  • Saldos posteriores (newbalance*) y errores contables: se evaluaron (escenario B) pero no se despliegan, porque no se conocen antes de autorizar.

Se crea ({{ m.features|length }} variables en el modelo)

  • Tiempo: hourOfDay, isNight.
  • Monto: logAmount para reducir la asimetría (los extremos no se eliminan: son señal).
  • Saldos: origZeroBefore, destZeroBefore, ratios monto/saldo.
  • Vaciado: drainsOrigin, amountMinusOrigBalance.
  • Categóricas: type, destPrefix → One-Hot Encoding.
  • Escalado: RobustScaler (mediana e IQR), resistente a colas extremas.

4 · Partición temporal

Se entrena con el pasado, se ajusta el umbral con el período siguiente y se evalúa con el futuro. No se balancean clases con remuestreo: se usa class_weight, que no altera los datos de evaluación. Las tasas por conjunto reflejan en parte el muestreo del archivo (ver hallazgo de calidad).

6 · Evaluación y selección

Métrica principal: PR-AUC en validación.

Resume precisión y recall en todos los umbrales y no se infla con el desbalance como la ROC-AUC.

Desempate: robustez.

Random Forest y HistGB empataron (PR-AUC 1,000). Se reentrenaron sin las variables de vaciado: HistGB mantuvo {{ ('%.4f' % m.results['hgb__sin_vaciado'].valid.pr_auc)|es }} y Random Forest {{ ('%.4f' % m.results['forest__sin_vaciado'].valid.pr_auc)|es }}. Ante patrones nuevos, depende menos de una única regla.

Umbral: máximo F2 en validación ({{ ('%.3f' % m.threshold)|es }}).

Se fija antes de mirar el conjunto de prueba, que se usa una sola vez.

Control de fuga.

El escenario B (con saldos posteriores) no mejora al A ({{ m.results[m.chosen ~ '__B'].test.confusion.fn }} vs {{ m.results[m.chosen].test.confusion.fn }} fraudes perdidos): el desempeño no depende de información posterior a la transacción.
