¿Son razonables estos resultados?

Un desempeño casi perfecto no es esperable en datos bancarios reales. Aquí se explica porque el dataset es simulado (PaySim): el {{ ('%.1f' % (m.dataset.drain.fraude_que_vacia * 100))|es }} % de los fraudes vacía exactamente la cuenta de origen y prácticamente ninguna operación legítima lo hace (probabilidad de fraude dado el vaciado: {{ ('%.2f' % (m.dataset.drain.p_fraude_si_vacia * 100))|es }} %).

Por eso la regla simple ya logra {{ ('%.1f' % (m.results.rule.test.recall * 100))|es }} % de recall. El valor del modelo está en el resto: recupera los fraudes que no siguen el patrón, con cero falsos positivos y sin variables posteriores a la transacción. Además, el archivo contiene períodos con sólo fraudes; evaluando únicamente donde conviven ambas clases (prevalencia real {{ ('%.2f' % (m.dataset.sampling.window_rate * 100))|es }} %), el modelo detecta {{ m.results[m.chosen].test_window.confusion.tp }} de {{ m.results[m.chosen].test_window.confusion.tp + m.results[m.chosen].test_window.confusion.fn }} con {{ m.results[m.chosen].test_window.confusion.fp }} falsos positivos. En producción habría que monitorear la deriva y reentrenar periódicamente.
